## 1. Понятия

![Понятия](img/graph-terms.svg)

**Граф** $G = (V, E)$: множество от **върхове** $V$ и множество от **ребра** $E$ — двойки върхове. Ще бележим $n = |V|$, $m = |E|$. Върховете номерираме $0, 1, \dots, n - 1$ (ако имат имена — пазим отделно речник име → номер).

| Понятие | Значение |
|---|---|
| **ненасочен** граф | ребро $\{u, v\}$ — в двете посоки (приятелство) |
| **насочен** граф | дъга $(u, v)$ — само от $u$ към $v$ (следване в Twitter, линк, „$u$ преди $v$“) |
| **съседи** на $u$ | върховете, с които $u$ е свързан с ребро |
| **степен** $\deg u$ | броят съседи; при насочен — **входна** и **изходна** степен |
| **път** | редица от върхове, всеки свързан със следващия; **дължина** = брой ребра |
| **цикъл** | път, който започва и свършва в един връх |
| **свързан** граф | между всеки два върха има път |
| **свързана компонента** | максимално свързано подмножество от върхове |
| **тегло** | число върху ребро (разстояние, цена) — седмица 14 |

Две полезни равенства. Всяко ребро добавя 1 към степента на **двата** си края, затова $\sum_u \deg u = 2m$ (лемата за ръкостисканията). И $m \le n(n-1)/2$ за ненасочен граф без примки — графите с $m \approx n^2$ са **гъсти**, с $m \approx n$ — **разредени**. Реалните графи почти винаги са разредени: в пътната мрежа всеки град има няколко съседа, не хиляди.

Дървото е свързан граф без цикли — затова има точно $n - 1$ ребра (седмица 09).

> [!TIP]
> **💡 Любопитно.** Теорията на графите започва през 1736 г. с Ойлер и седемте моста на Кьонигсберг: може ли да се мине по всеки мост точно веднъж? Ойлер доказва, че не може — защото повече от два върха имат нечетна степен. Първата теорема в областта е за степени.

## 2. Представяне

![Представяния](img/representations.svg)

| | Матрица на съседство | Списъци на съседство | Списък на ребрата |
|---|---|---|---|
| памет | $\Theta(n^2)$ | $\Theta(n + m)$ | $\Theta(m)$ |
| има ли ребро $u$–$v$? | $\Theta(1)$ | $\Theta(\deg u)$ | $\Theta(m)$ |
| всички съседи на $u$ | $\Theta(n)$ | $\Theta(\deg u)$ | $\Theta(m)$ |
| подходящо за | гъсти графи, малко $n$ | почти всичко | сортиране на ребрата (Kruskal, седмица 14) |

**Матрицата** е проста и отговаря за $\Theta(1)$ на „свързани ли са $u$ и $v$“. Но $n = 100\,000$ върха — $10^{10}$ клетки (10 GB), почти всички нули. И обхождането на съседите е $\Theta(n)$, колкото и малко да са те.

**Списъците** са стандартът: за всеки връх — вектор със съседите му. Обхождането на всички съседи на всички върхове е $\Theta(n + m)$ — точно колкото е графът.

```cpp
std::vector<std::vector<int>> adj(n);
adj[u].push_back(v);
adj[v].push_back(u);  // undirected: both directions
```

Класът `Graph` в `starter/graph.h` е точно това. За насочен граф `addEdge(u, v)` добавя само `u → v`.

> [!NOTE]
> **🔬 За напреднали: CSR.** Вектор от вектори е $n$ отделни алокации — пръснати в паметта. **Compressed sparse row** пази всички съседи в **един** масив `targets`, а `offset[u]` казва откъде започват съседите на $u$ (до `offset[u+1]`). Същата информация, половината памет, по-малко промахи в кеша (седмица 02). Неудобен за добавяне на ребра — строи се веднъж. Ползва се в библиотеки за графи и за разредени матрици; в бенчмарка (§10) е ~1.5× по-бърз от списъците.

## 3. Обхождане в ширина (BFS)

**Обхождане в ширина** (breadth-first search) от връх $s$: първо всички на разстояние 1, после всички на разстояние 2, … — „вълни“ около $s$. Инструментът е **опашка** (седмица 07).

<div align="center">

![BFS 1](img/bfs-1.svg)

![BFS 2](img/bfs-2.svg)

![BFS 4](img/bfs-4.svg)

</div>

```cpp
std::vector<int> dist(n, -1);   // -1: not discovered
std::queue<int> q;
dist[s] = 0;
q.push(s);
while (!q.empty()) {
    int u = q.front();
    q.pop();
    for (int v : g.neighbors(u)) {
        if (dist[v] == -1) {          // first time we see v:
            dist[v] = dist[u] + 1;    // mark it NOW (on push)
            q.push(v);
        }
    }
}
```

**Защо дава най-късите пътища:** опашката винаги съдържа върхове от най-много две съседни нива — $d$ и $d + 1$ — и всички от ниво $d$ са преди тези от $d + 1$. Затова връх на разстояние $d + 1$ се открива за пръв път **от** връх на разстояние $d$ — по най-краткия път.

**Маркирайте при слагане, не при вадене.** Ако маркирате, когато вадите от опашката, един връх може да влезе в нея многократно (от всеки свой съсед) — опашката расте до $\Theta(m)$ и разстоянията може да станат грешни.

**Пътят, не само дължината:** пазете `parent[v]` — върха, от който $v$ е открит. Веригата `t, parent[t], parent[parent[t]], …, s` е най-краткият път наобратно. Ребрата `parent[v] → v` образуват **дървото на BFS** (оранжевото на фигурата).

$\Theta(n + m)$: всеки връх влиза в опашката най-много веднъж, всяко ребро се гледа най-много два пъти.

> [!TIP]
> **💡 Любопитно: шест (или четири) ръкостискания.** BFS по графа на Facebook през 2011 г. (721 милиона потребители, 69 милиарда приятелства) показва, че средното разстояние между двама потребители е **4.74** — по-малко от „шестте ръкостискания“ от експеримента на Милграм (1967). Числото на Ердьош е разстоянието в BFS в графа на съавторствата от Пал Ердьош.

## 4. Неявни графи: лабиринт

Графът не винаги е записан. В лабиринт **върхът** е свободна клетка, а **ребрата** — до четирите съседни свободни клетки. Не строим списъци на съседство — смятаме съседите при нужда:

```cpp
const int dr[] = {-1, 1, 0, 0}, dc[] = {0, 0, -1, 1};
for (int k = 0; k < 4; ++k) {
    int nr = r + dr[k], nc = c + dc[k];
    if (nr < 0 || nr >= rows || nc < 0 || nc >= cols) continue;   // outside
    if (grid[nr][nc] == '#' || dist[nr][nc] != -1) continue;      // wall or seen
    dist[nr][nc] = dist[r][c] + 1;
    q.push({nr, nc});
}
```

![Лабиринт](img/maze.svg)

Същият BFS, $\Theta(\text{клетки})$. Така работят „кофата с боя“ в графичните редактори (flood fill), търсенето на път в стратегически игри и разпределянето на проводници в интегрални схеми (Lee, 1961). Състоянията на пъзел (кубчето на Рубик, „15“) също са неявен граф — BFS намира най-краткото решение.

## 5. Обхождане в дълбочина (DFS)

**Обхождане в дълбочина** (depth-first search): от текущия връх отиди в **първия** непосетен съсед; когато няма такъв — върни се назад. Като да излезеш от лабиринт с ръка на стената. Естествено рекурсивно:

```cpp
void dfsVisit(const Graph& g, int u, std::vector<char>& seen, std::vector<int>& out) {
    seen[u] = 1;
    out.push_back(u);                 // pre-order: on first visit
    for (int v : g.neighbors(u))
        if (!seen[v]) dfsVisit(g, v, seen, out);
}
```

![DFS](img/dfs.svg)

$\Theta(n + m)$, като BFS. Но DFS **не** дава най-кратки пътища: на фигурата DFS стига до 8 по път от 6 ребра, а най-краткият е 3.

**Рекурсията пак има дъно** (седмица 09): дълбочината е до $n$. Граф-път от милион върха препълва стека. Итеративната версия заменя стека на извикванията с явен стек от двойки (връх, индекс на следващия съсед за пробване) — така редът на посещение е **същият** като при рекурсията (задача 7).

> [!WARNING]
> Чест неверен „итеративен DFS“: BFS кодът с `std::stack` вместо `std::queue`. Той обхожда всичко, но в **друг** ред (съседите се обръщат и се маркират при слагане, а не при посещение) — не е DFS и не става за цикли и топологична подредба. Тестът на задача 7 сравнява реда с рекурсивния.

> [!TIP]
> **💡 Любопитно.** DFS е по-стар от компютрите: френският инженер Шарл Пиер Тремо описва през XIX век метод за излизане от лабиринт с маркиране на коридорите — по същество DFS с връщане назад. BFS за най-кратък път в лабиринт е публикуван от Едуард Мур през 1959 г.

## 6. Свързани компоненти

В ненасочен граф: пуснете обхождане (BFS или DFS) от всеки връх, който още няма компонента; всичко, до което стига, е една компонента. Общо $\Theta(n + m)$ — всяко обхождане минава само през своята компонента.

```cpp
std::vector<int> comp(n, -1);
int next = 0;
for (int s = 0; s < n; ++s)
    if (comp[s] == -1) { /* BFS from s, label everything with next */ ++next; }
```

Приложения: „има ли път между $u$ и $v$“ за $\Theta(1)$ след предварителна обработка; групи в социална мрежа; острови в карта (компоненти в лабиринт). Ако ребрата **се добавят** с времето, по-бързо е „обединение на множества“ (union-find) — седмица 14.

## 7. Цикли и топологична подредба

### 7.1. Цикъл в насочен граф

DFS с **три цвята**:

- **бял** — непосетен;
- **сив** — в стека на рекурсията (на текущия път от корена на DFS);
- **черен** — завършен (всичките му наследници са обходени).

Ребро към **сив** връх е ребро назад по текущия път — **цикъл**. Ребро към **черен** — не: той е завършен и от него не се стига обратно до нас (иначе щяхме да го видим, докато беше сив).

![Цикъл с три цвята](img/cycle-colours.svg)

Затова два цвята („посетен“/„непосетен“) не стигат: две различни пътеки до един връх ($0 \to 1 \to 3$ и $0 \to 2 \to 3$) не са цикъл.

### 7.2. Топологична подредба

**Топологична подредба** на насочен граф: подредба на върховете, в която всяка дъга $u \to v$ има $u$ преди $v$. Съществува **точно** когато графът няма цикли (DAG — directed acyclic graph). Задачи с предпоставки: курсове, стъпки на компилация, зависимости на пакети, клетки в електронна таблица.

![Топологична подредба](img/topo.svg)

**Алгоритъм на Kahn (1962):** върховете с входна степен 0 нямат предпоставки — те са готови. Вземете един, „махнете“ дъгите му (намалете входната степен на съседите), и който стигне 0 — също е готов. Ако накрая има невзети върхове — те са в цикъл.

```cpp
std::vector<std::size_t> in = inDegrees(g);
std::queue<int> ready;                    // (or a min-heap, for "smallest first")
for (int u = 0; u < n; ++u) if (in[u] == 0) ready.push(u);
while (!ready.empty()) {
    int u = ready.front(); ready.pop();
    order.push_back(u);
    for (int v : g.neighbors(u))
        if (--in[v] == 0) ready.push(v);
}
if (order.size() != n) /* cycle */;
```

**Чрез DFS:** запишете всеки връх, когато **завърши** (стане черен); обратният ред е топологична подредба — връх завършва след всичко, до което може да стигне.

И двете са $\Theta(n + m)$. Kahn е по-естествен за „кое може да се направи сега“ (паралелни задачи); DFS — когато и без това правите DFS.

> [!TIP]
> **💡 Любопитно.** `make`, CMake и Ninja строят графа на зависимостите между файловете и компилират в топологичен ред; `make -j8` е Kahn с 8 „работника“, които вземат готови задачи. Цикъл в зависимостите (`a.h` включва `b.h`, който включва `a.h`) е грешка точно защото топологична подредба няма.

## 8. Двуделни графи

Граф е **двуделен** (bipartite), ако върховете се делят на две групи, така че всяко ребро е **между** групите: студенти и курсове, работници и задачи, кандидати и позиции.

![Двуделен граф](img/bipartite.svg)

Проверка с BFS: коренът — цвят 0; всеки съсед — обратния цвят; съсед със **същия** цвят → не е двуделен. Граф е двуделен точно когато **няма цикъл с нечетна дължина** (König, 1936): нечетен цикъл не може да се оцвети с два цвята, редувайки ги.

## 9. BFS или DFS?

| | BFS | DFS |
|---|---|---|
| структура | опашка | стек (рекурсия) |
| ред | по нива — разстояние 0, 1, 2… | по-навътре, после назад |
| най-кратък път (без тегла) | **да** | не |
| памет | най-широкото ниво (до $\Theta(n)$) | най-дългият път (до $\Theta(n)$) |
| цикли, топологична подредба | (Kahn — по-скоро броене) | **да** — три цвята, ред на завършване |
| компоненти, достижимост | да | да |
| сложност | $\Theta(n + m)$ | $\Theta(n + m)$ |

Следващия път: **тегла** по ребрата — BFS вече не дава най-къс път (един дълъг мост може да е по-лош от три къси пътя). Алгоритъмът на Дейкстра е „BFS с пирамида вместо опашка“ (седмица 11).

## 11. Обобщение

| Тема | Да запомните |
|---|---|
| Граф | $V$, $E$; насочен / ненасочен; $\sum \deg = 2m$; реалните са разредени |
| Представяне | матрица $\Theta(n^2)$ — само за гъсти; списъци $\Theta(n + m)$ — стандартът |
| BFS | опашка; маркирай при слагане; разстояния = най-кратки пътища; `parent` → самият път |
| Неявен граф | съседите се смятат при нужда (лабиринт, състояния на пъзел) |
| DFS | рекурсия (или явен стек от (връх, индекс)); не дава най-кратки пътища; дълбочина до $n$ |
| Компоненти | обхождане от всеки неозначен връх |
| Цикъл (насочен) | DFS с три цвята; ребро към сив = цикъл |
| Топологична подредба | само за DAG; Kahn (входни степени) или обратен ред на завършване в DFS |
| Двуделност | BFS с два цвята; ⇔ няма нечетен цикъл |
| Сложност | всичко днес е $\Theta(n + m)$ |

## 13. Литература

- T. Cormen и др. *Introduction to Algorithms* — гл. 22 „Elementary Graph Algorithms“ (представяне, BFS, DFS, топологична подредба, бели/сиви/черни върхове).
- R. Sedgewick, K. Wayne. *Algorithms*, 4th ed. — §4.1 „Undirected Graphs“, §4.2 „Directed Graphs“; [онлайн материали](https://algs4.cs.princeton.edu/41graph/).
- S. Skiena. *The Algorithm Design Manual* — гл. 7 „Graph Traversal“ (много практически примери).
- A. B. Kahn. „Topological sorting of large networks“, *Communications of the ACM* 5(11), 1962.
- E. F. Moore. „The shortest path through a maze“, 1959.
- L. Backstrom и др. „Four Degrees of Separation“, WebSci 2012 (BFS по графа на Facebook).
- [VisuAlgo — Graph Traversal](https://visualgo.net/en/dfsbfs) — анимации на BFS и DFS.
