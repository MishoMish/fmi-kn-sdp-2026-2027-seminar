## Част А — загрявка без тестове

Пишете в обикновен файл и компилирате с една команда:

```bash
g++ -std=c++17 -Wall -Wextra -g a1.cpp -o a1 && ./a1
# по-добре — с AddressSanitizer (Linux, macOS):
g++ -std=c++17 -Wall -Wextra -g -fsanitize=address,undefined a1.cpp -o a1 && ./a1
```

Какво значи всяка част от командата:

| Част | Какво прави |
|---|---|
| `g++` | компилаторът за C++ (GCC). На macOS `g++` всъщност е Clang — флаговете са същите. |
| `-std=c++17` | компилира по стандарта C++17. Без него компилаторът ползва своя версия по подразбиране, която може да е друга. |
| `-Wall` | включва основните предупреждения (warnings): неизползвани променливи, сравнение на `int` с `size_t`, функция без `return` и т.н. Името значи „all“, но не са всички. |
| `-Wextra` | включва още предупреждения, които `-Wall` пропуска, например неизползван параметър. |
| `-g` | добавя информация за дебъгване: имената на функциите и номерата на редовете. Така ASan и дебъгерът казват `a1.cpp:27`, а не само адрес в паметта. |
| `-fsanitize=address` | **AddressSanitizer (ASan)**: проверява всеки достъп до паметта, докато програмата работи. Хваща четене извън масива, използване на освободена памет (use-after-free), двойно `delete[]` и изтекла памет (leak). Програмата спира с отчет, който казва какво и на кой ред. |
| `-fsanitize=undefined` | **UBSan**: хваща недефинирано поведение (undefined behaviour), например препълване на `int`, деление на нула, грешно отместване на битове. Двата sanitizer-а се пишат заедно: `address,undefined`. |
| `a1.cpp` | файлът, който компилирате. |
| `-o a1` | името на изпълнимия файл (`o` от „output“). Без него файлът се казва `a.out`. |
| `&&` | „и после“: пуска втората команда **само ако** първата е успяла. Ако има грешка при компилация, старият `a1` няма да се пусне по погрешка. |
| `./a1` | пуска програмата. `./` значи „в текущата папка“. |

Предупрежденията не спират компилацията, но **четете ги**: почти винаги сочат истински бъг. ASan забавя програмата около 2 пъти, затова е за проверка, не за мерене на време. На Windows с MinGW `-fsanitize` не работи; ползвайте Compiler Explorer или WSL.

Става и с [Compiler Explorer](https://godbolt.org) или с друг онлайн компилатор.

### Задача 1 ★ — растеж

Тестове: `Task 1`

| Метод | Поведение |
|---|---|
| `reallocate(newCapacity)` (private) | нов буфер с точно `newCapacity` елемента, старите елементи в него, старият буфер освободен; `newCapacity == 0` → `data_ = nullptr` |
| `reserve(n)` | ако `n > capacity()` — `reallocate(n)`; иначе нищо |
| `pushBack(const T&)` | ако няма място: нов капацитет = 1 за празен масив, иначе `2 * capacity()` |
| `popBack()` | премахва последния; присвоява `T{}` на освободеното място; `std::out_of_range` при празен |

**Капанът:** `a.pushBack(a[0])` при пълен масив. `value` е референция към елемент в **стария** буфер. Ако го прочетете, след като сте освободили стария буфер (или след като сте преместили елементите от него), четете боклук. Тестът `pushBack of an element of the same array` може да мине „случайно“ без ASan — пуснете го с `asan` preset-а.

<details>
<summary>Насока</summary>

Редът при пълен масив: (1) нов буфер; (2) `fresh[size_] = value;` — **преди** всичко друго; (3) прехвърлете старите; (4) `delete[] data_;`, `data_ = fresh;`, обновете капацитета; (5) `++size_`.

</details>

**Въпрос за размисъл.** Тестът `n pushBacks cost O(n) element transfers in total` позволява до $3n$ копирания + премествания за $n = 1000$. Колко точно прави вашата реализация? Изведете формулата.

### Задача 2 ★★ — правилото на петте

Тестове: `Task 2`

| Функция | Изискване |
|---|---|
| копиращ конструктор | дълбоко копие: собствен буфер (капацитетът може да е точно `size()`) |
| копиращ оператор `=` | copy-and-swap, както в седмица 03; работи при `a = a` |
| преместващ конструктор | **краде** буфера: `data()` на новия е същият указател; оригиналът остава празен (size 0, capacity 0, `nullptr`) и използваем; **нито едно** копиране или преместване на елемент |
| преместващ оператор `=` | освобождава собственото си съдържание, взима буфера на другия, другият остава празен |

И двете преместващи операции трябва да са `noexcept` — тестът го проверява по време на компилация (`STATIC_REQUIRE`).

<details>
<summary>Насока</summary>

`std::exchange(other.data_, nullptr)` връща стария `other.data_` и едновременно го нулира — идеално за списъка за инициализация на преместващия конструктор.

Преместващият оператор може да се напише с преместващия конструктор и `swap`: `DynamicArray taken(std::move(other)); swap(taken); return *this;`.

</details>
